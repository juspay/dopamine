# X Bookmarks Spike Plan (throwaway, go/no-go)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to run this plan in the current session. Steps use checkbox (`- [ ]`) syntax. This is a labelled spike: no product code is merged, and keeping anything it produces is a new request.

**Goal:** Learn, against the live site, whether X lets a logged-in Chrome profile read bookmarks by observation, and what the response looks like, so the harvester plan can be written or dropped.

**Architecture:** A throwaway Node script on a never-merged branch launches Chrome on `~/.dopamine-x-profile` through the existing `launchChrome`, opens `https://x.com/i/bookmarks`, and records the GraphQL responses the page fetches over CDP. It stores the shape (key paths and types), not content.

**Tech Stack:** Node, `chrome-remote-interface`, the compiled `dist/pipeline/piggyback/chrome.js`.

**Spec:** `docs/superpowers/specs/2026-10-17-youtube-x-sources-design.md` section 3.0. Research input: `/Users/sachinsharma/Documents/dopamine-research/X-BOOKMARKS-RESEARCH.md`. **Runs in parallel with** the groundwork plan; it needs only the login.

**Branch:** `workforge create -t chore -n x-spike -y`; never opened as a PR. Keep the findings document and the synthetic fixtures; delete the branch.

## Global Constraints

- Read only: no click on like, bookmark, follow, post or any other control; observe responses, never call X endpoints ourselves, never scrape page layout.
- At most 2 runs per day during the spike, at least 1 hour apart; scroll pauses of 2 to 4.5 seconds with jitter; at most 10 scrolls per run.
- **Stop at once** on a login wall (`/i/flow/login`, `/login`), a challenge or "unusual activity" page, a verification or captcha prompt, an HTTP 429, or any lock or suspension notice: close Chrome, write down exactly what appeared, make no further attempt for 24 hours, report to Sachin. Do not work around it.
- No stealth plugins, fingerprint patching, proxies or captcha solving.
- The profile directory stays outside the repo with mode 700. Nothing scraped (post text, handles, ids, URLs of media) is written to the repo or to a findings file: only key paths, types, counts and timings. Fixtures are written by hand from those shapes.
- Sachin has accepted that this goes against X's terms and may restrict the account.

## Review Focus

1. The page redirects to a login or challenge flow mid-run: abort, record the URL path only, no retry.
2. `Bookmarks` is served as a different operation name, or through a path other than `/i/api/graphql/<id>/<name>`: log every operation name seen, do not assume.
3. A page with `count` results but fewer parseable tweets (tombstones, unavailable, promoted): record each wrapper type's count.
4. The feed ends without a clear signal: record whether the end is no cursor, a repeated cursor, or empty pages.
5. Headless and headed disagree on the same profile: record both, do not tune until one passes.

### Task 1: Headless capture of the response shape

**Files:** Create `spikes/x-bookmarks/probe.mjs` (spike branch only), output to `spikes/x-bookmarks/out/` (git-ignored).

**Interfaces:** `node spikes/x-bookmarks/probe.mjs [--headed] [--scrolls=10]` after `npm run build`. Uses `launchChrome(9456, profile)`/`waitForPort` for headless; with `--headed` it spawns Chrome itself with the same flags minus `--headless=new`. Writes `out/shape-<timestamp>.json` with: every GraphQL operation name seen and its count; for any response whose operation name contains `Bookmark`: the key-path inventory (path to each leaf with its JSON type, no values), tweet entries per response, wrapper types seen, cursor entry presence, `note_tweet` and video-variant presence, and the key set of the author object over up to 20 samples; request count, elapsed time, and the stop reason (`done`, `login-wall`, `challenge`, `429`).

- [ ] **Step 1:** Write the probe: attach CDP (`Network.enable`, `Network.responseReceived`, `Network.getResponseBody` after `loadingFinished`), navigate, wait 6 s, then scroll with randomised 2.0 to 4.5 s pauses; after each step test the page URL and the body text for the stop conditions above and exit with the reason.
- [ ] **Step 2:** Dry-run the stop logic without X: point the probe at a local page that redirects to `/login` (a 10-line `http.createServer`), expected stop reason `login-wall` and a clean Chrome exit.
- [ ] **Step 3:** Run it once headless against X. Expected: `done` or a recorded stop reason; Chrome closed in both cases.
- [ ] **Step 4:** Read the shape file and note the answers to the six research items: operation name and URL shape, response path, author field location (`core.screen_name` or `legacy`), text and `note_tweet` fields, entries per response, cursor behaviour.
- [ ] **Step 5:** Commit on the spike branch only: `chore(spike): probe x bookmarks response shape`.

### Task 2: Depth and end of feed

**Files:** Reuse `probe.mjs` with `--scrolls=` set; no new file.

- [ ] **Step 1:** One run, at least 1 hour after Task 1, with `--scrolls=10`; keep the same 10-scroll ceiling. Record how many bookmarks that reaches and whether the cursor continues.
- [ ] **Step 2:** If Sachin knows roughly how many bookmarks he has, compare; if the feed was nowhere near exhausted, record the per-scroll yield so the harvester's `X_HARVEST_SCROLLS` can be sized. Do not scroll deeper than 10 in the spike.
- [ ] **Step 3:** Record the end-of-feed signal if reached (Review Focus 4); otherwise record "not reached at 10 scrolls".

### Task 3: Headed comparison (only if headless failed)

**Files:** None.

- [ ] **Step 1:** Skip this task if both headless runs ended `done` with no challenge. Otherwise, after the 24-hour wait, run one headed (`--headed`) run, same profile, same limits.
- [ ] **Step 2:** If the headed run passes where headless failed, test the scheduled case: a temporary launchd agent `com.dopamine.x-spike` (`StartInterval` 120, running `node spikes/x-bookmarks/probe.mjs --headed`) loaded with `launchctl bootstrap gui/$(id -u) <plist>`, once with the screen unlocked and once locked (lock with Ctrl+Cmd+Q); remove it afterwards with `launchctl bootout gui/$(id -u)/com.dopamine.x-spike`. Record whether a window opened and whether capture worked in each state.
- [ ] **Step 3:** If the headed run is also challenged, stop. That is a no-go.

### Task 4: Findings, fixtures and decision

**Files:** Create `docs/superpowers/plans/2026-10-18-x-spike-findings.md` (on the design branch) and the shapes for `src/__tests__/fixtures/x/` (written by hand, synthetic values only, handed to the harvester plan).

- [ ] **Step 1:** Write the findings: the observed value for each of the six research items; counts of wrapper types; the stop reason of every run with its timestamp; headless versus headed result; the launchd result if run.
- [ ] **Step 2:** Write three synthetic fixtures from the observed shapes: a normal bookmark page, a page with a long post (`note_tweet`), a quote, a video post and a tombstone, and a page ending without a cursor. Use invented ids, handles and text.
- [ ] **Step 3:** Apply the decision rule and write it at the top of the findings.
  - **GO headless:** two headless runs at least 1 hour apart both ended `done`; at least 10 bookmarks (or all of them if fewer) were captured; at least 95% of entries had an id, author handle and text or media; the end-of-feed behaviour is understood.
  - **GO headed:** headless is blocked but headed passed twice and the launchd test passed (unlocked, and locked if Sachin leaves the screen locked at 06:00).
  - **NO-GO:** anything else, including any challenge on a headed run. X is not built; Sachin is told, and no workaround is tried.
- [ ] **Step 4:** Commit the findings to the design branch (`docs(sources): record the x bookmarks spike result`), delete the spike branch and `spikes/`, and tell Sachin the decision. On GO, finish the harvester plan (`2026-10-18-x-harvester.md`) with the observed paths and settings.
